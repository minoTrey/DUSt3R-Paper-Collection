# 후보 큐 (Discovery and Curation)

이 폴더는 자동 발견 후보와 실제 문서화 상태를 연결한다.
발견은 포함 결정이나 원문 검증이 아니다. `queue.jsonl`은 수집 메타데이터이며
`reconciliation.tsv`는 문서의 arXiv ID와 과거 triage를 대조한 기록이다.

## 상태와 근거

```text
new → reviewed → added
              → rejected
```

- **new**: 본문과 관련성 검토가 남아 있다.
- **reviewed**: 사람이 관련성과 원문을 검토한 후보다. 검토 근거를 함께 남긴다.
- **added**: 동일한 arXiv ID의 문서가 존재한다. 과거 문서 전체를 새로 검증했다는 뜻은 아니다.
- **rejected**: 명시한 제외 결정이 있다. 과거 OUT 27건과 이번 원문 범위 검토의 제외 7건을 구분한다.

`tools/reconcile_candidates.py`는 제목으로 관련성이나 중복을 단정하지 않는다.
같은 ID가 여러 문서에 있거나 과거 IN/OUT과 문서가 충돌하면 변경 전에 실패한다.

## 문서화 절차

1. `python tools/reconcile_candidates.py`로 상태를 조회한다.
2. 후보의 arXiv ID·제목·저자를 확인한다. 기존 문서의 다른 제목·동명 논문도 확인한다.
3. 원문을 읽고 [논문 템플릿](../docs/paper-template.md)의 일곱 섹션을 작성한다.
   입력·출력·좌표계·해결할 문제·핵심 방법을 구체적으로 설명한다.
4. `verify_metadata.py --only <slug> --out raw/metadata_<slug>.json`으로 venue를 확인한다.
   조회 실패를 미출간 확정으로 바꾸지 않는다. `PREPRINT?`는 문서에 `UNKNOWN`과 한계로 기록한다.
5. 수치에 PDF 버전·Table·데이터셋·프로토콜·단위를 적는다. 표의 셀과 문장을 직접 대조한다.
6. `build_papers_list.py`, `update_stats.py`, `build_fact_cards.py`로 생성 문서를 맞춘다.
7. `reconcile_candidates.py --write` 후 `reconcile_candidates.py --check`로 상태를 검사한다.
8. `verify_all.py`의 기본 오프라인 검사와 변경 논문의 PDF 검증을 실행한다. `--fast` 인자는 없다.
9. `log.md`에 검토 범위·검증 결과·잔여 항목을 기록한다.

PDF는 `docs/papers/`의 로컬 캐시에만 두며 커밋하지 않는다.
메타데이터·수치 출현 검사는 논문 내용의 정확성이나 실험 재현을 보증하지 않는다.

## 주간 discovery와 연결하는 제안

현재 `.github/workflows/discover.yml`은 월요일 06:00 UTC에 후보를 수집한다.
이번 작업은 workflow·주기·권한을 변경하지 않는다. 아래는 후속 운영 제안이다.

1. Discovery 다음에 정확한 ID로 문서·기존 제외 기록을 먼저 대조한다.
2. 관련성 검토자는 한 번에 소수의 후보를 고르고 선택 이유·제외 이유를 기록한다.
3. 원문 검토자는 입력·출력·방법·수치 출처·실패 사례를 확인한 뒤 검토용 PR을 만든다.
4. Merge 후 added 상태와 생성 인덱스를 다시 대조한다. 원문을 읽지 않은 후보는 new로 남긴다.
5. S2 요청 제한·학회 색인 지연·이름 충돌은 별도 재검토 항목으로 유지한다.
